# Technical documentation checklist

- Audience, prerequisites, outcome, and non-goals are explicit.
- Claims match current code and authoritative sources.
- Steps follow the reader's actual task order.
- Commands, paths, and configuration names are exact.
- Expected success and meaningful failure signals are stated.
- Examples avoid hidden state and destructive side effects.
- Links and commands have been validated.
- Future work is clearly separated from current behavior.
