# v0.1.1 upgrade: migration 010

v0.1.1 makes the published revision's classification authoritative for
imported-skill eligibility and adds dedicated append-only revision
classification events. Migration 010 establishes one truthful transaction-time
baseline for each existing revision current projection; it does not rewrite raw
candidate observation history.

This is a maintenance upgrade, not a rolling deployment:

1. Stop traffic and drain every SkillWire, ingestion, and administration writer.
2. Keep PostgreSQL running and take a validated, independently restorable
   pre-upgrade backup.
3. Run `docker compose run --rm migrate` from the v0.1.1 image. A lock or
   statement timeout is a failed upgrade; find the forgotten writer or rehearse
   an appropriate bounded timeout, then rerun.
4. Rerun the migrator, then run catalog and advisory verification from the same
   image.
5. Start only v0.1.1 or a later post-010-compatible image and require
   `/health/ready` before traffic.

Migration 010 is transactional and idempotent. Failure leaves schema 009 usable.
After success, never roll back only the application to a pre-010 image. To cross
back over the schema boundary, stop writers and restore the pre-upgrade database
backup together with the matching old image; all post-backup database changes
will be lost. Full details are in
[deployment and operations](../operations.md#migrations).
